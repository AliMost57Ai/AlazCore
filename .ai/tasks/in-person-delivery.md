# Task: درگاه پرداخت + تحویل حضوری (payments-gateway-pickup)

**تاریخ شروع:** 2026-10-03 — **پشته:** Node.js/Next.js (فروشگاه + پنل Core) + SQLite multi-tenant
**برنچ:** ادامه کار روی `superAdminDash` (تغییرات UI قبلی در کار است؛ برنچ جدید پس از تایید کاربر)

## درخواست کاربر (سه بخش)

- **A — باگ زرین‌پال sandbox:** «ایجاد درخواست پرداخت ناموفق بود.»
- **B — منوی تراکنشهای درگاه:** نمایش اینکه پرداخت از کدام درگاه بوده + اطلاعات پرداختی که درگاه بعد از تایید برمی‌گرداند (شماره کارت، کارمزد، کد مرجع…) — نمونه تصویر کاربر.
- **C — تحویل حضوری:** کامل — مالک (مدیریت نقاط/بازه‌ها/تعطیلات + روش ارسال + منوی سفارشات + اعلان‌ها + گزارش مالی + دسترسی نقش‌ها)، مشتری (انتخاب نقطه + نزدیک شما + تقویم یک‌هفته + اسلات با ظرفیت)، Core (فعال/غیرفعال per-domain + پنهان‌سازی کامل).

## سند راه‌حل (solution-architect)

### A — ریشه باگ زرین‌پال (پیدا و تأییدشده)
زرین‌پال v4 روی **موفقیت** هم `"errors": []` برمی‌گرداند (تأیید با fetch واقعی به sandbox از همین ماشین). آرایه خالی در JS truthy است → `if (envelope.errors)` مسیر خطا می‌رود → پیام fallback. اصلاح: تشخیص خطای واقعی (آرایه غیرخالی یا آبجکت) در `lib/zarinpal.ts` + تست.

### B — تراکنش‌های درگاه
- ستون جدید `OnlinePaymentTransaction.verifyPayload` (JSON پاسخ verify) + `cardPan` — در callback پس از verify ذخیره می‌شود (زرین‌پال: card_pan/fee/fee_type؛ سایر درگاه‌ها هر extra برگردانند).
- DTO + جدول: ستون «درگاه» (برچسب فارسی از نگاشت client-safe در payment-defs) + ردیف آکاردئونی جزئیات (authority، کد مرجع، شماره کارت، کارمزد، سفارش) — بدون مودال، هم‌الگوی سفارش‌ها؛ موبایل کارت.

### C — تحویل حضوری (pickup)
**اسکیما (فروشگاه + مهاجرت سبک site-db):**
- `PickupLocation` (title/address/lat/lng/isActive) — نقاط مراجعه
- `PickupSlot` (locationId، startMinute/endMinute از نیمه‌شب، capacity)
- `PickupHoliday` (date ISO یکتا، title) — تعطیلی سراسری فروشگاه
- `ShippingMethod.kind ('courier'|'pickup')` + `pickupLocationId` — روش ارسال از نوع تحویل حضوری که به یک نقطه بایند است
- `Order.pickupLocationId/pickupSlotId/pickupDate` — رزرو = خود سفارش (لغو → ظرفیت آزاد؛ بدون مدل جدا)
- Core: `Domain.inPersonDelivery Boolean` + لایسنس `inPersonDelivery` + فرم دامنه

**دسترسی‌ها:** `/settings/pickup` و `/orders/pickup` در ASSIGNABLE_MENUS (گروه سفارشات و تنظیمات).

**مالک:**
- `/settings/pickup` — CRUD نقطه + بازه‌های زمانی با ظرفیت + روزهای تعطیل + انتخاب موقعیت (lat/lng دستی — نقشه خارج از اسکوپ)
- روش‌های ارسال: سکشن «تحویل حضوری» با فعال/غیرفعال‌کردن هر نقطه به‌عنوان روش ارسال
- `/orders/pickup` — لیست سفارش‌های تحویل حضوری با جستجو (شناسه/مشتری/موبایل/نقطه) و فیلتر (امروز/رزروهای پیش‌رو/تحویل‌شده/همه) + عملیات «تحویل شد» (paid → delivered مستقیم برای pickup)
- BellMenu: «رزروهای تحویل حضوری» و «تحویل‌شده‌های حضوری» به تفکیک — فقط وقتی فیچر فعال است
- حسابداری: ستون روش تحویل + فیلتر تحویل حضوری/ارسالی

**مشتری (checkout):** ترتیب پله‌ها عوض می‌شود: روش ارسال → آدرس/رزرو → پرداخت. با انتخاب روش pickup: رادیوی نقاط (badge «نزدیک شما» با geolocation و haversine ≤ ۱۰km)، نوار ۷ روز آینده (تعطیل = غیرفعال)، اسلات‌های همان روز با ظرفیت باقی‌مانده؛ رزرو در API checkout با چک ظرفیت + اسنپ‌شات در deliveryAddress. بدون آدرس مشتری، هزینه ارسال صفر.

**Core:** سوییچ در فرم دامنه؛ خاموش = همه منوها/صفحات/فیلترها/اعلان‌ها/روش ارسال pickup در فروشگاه پنهان (license.ttl ۶۰s).

### تحلیل تکمیلی خود من (اضافه‌شده)
- ظرفیت رزرو با فیلتر `status != cancelled` تا لغو، ظرفیت را آزاد کند
- رزرو در تراکنش checkout با چک مجدد ظرفیت (race محدودِ قابل‌قبول مثل oversell P3)
- روش ارسال pickup فقط وقتی فعال است که نقطه‌اش isActive باشد؛ حذف نقطه = خاموشی روش
- تاریخ رزرو ISO yyyy-mm-dd + برچسب جلالی در نمایش؛ اسلات‌های گذشته امروز غیرفعال
- باکس داشبورد/شمارنده منو بر پایه همان کوئری لیست (یک عدد، مثل خالی‌فروشی)

## دام‌ها و نکات
- `component={Link}` از RSC به Button کلاینت رد نمی‌شود → `component="a"`
- SESSION: امضای دستی کوکی برای curl باید با secret کامل .env باشد (`cut -d=` کاراکتر `=` پایانی base64 را می‌بُرد)
- curl ویندوز + فارسی inline → «؟» در دیتابیس (باز هم تأیید شد) — حتماً `--data-binary @file`
- در sandbox زرین‌پال سقف مبلغ تراکنش ۲٬۰۰۰٬۰۰۰٬۰۰۰ ریال است — سفارش‌های بزرگ‌تر خطای -9 می‌گیرند (رفتار درگاه، باگ ما نیست)
- لایسنس کش ۶۰ثانیه‌ای: بعد از تغییر سوییچ Core تا یک دقیقه در فروشگاه اعمال می‌شود (رفتار مستند)

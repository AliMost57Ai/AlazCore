# قوانین نقش‌ها و گردش کار (Agents Workflow)

- همیشه با project-manager شروع کن مگر کاربر صریحاً یک نقش را نام ببرد.
- این پروژه سه پشته دارد: **Node.js/Next.js** (با Mantine UI)، **.NET**
  (Framework 4.5-4.8 و Core 6+)، و **دیتابیس** روی SQL Server/PostgreSQL/
  SQLite. project-manager و solution-architect باید در ابتدای هر فیچر
  پشته(های) درگیر را صراحتاً تشخیص/تعیین کنند؛ سایر agentها بدون این
  تشخیص کار نمی‌کنند.
- توالی پیش‌فرض پایپ‌لاین:
  1. solution-architect (طرح راه‌حل + تعیین پشته و موتور دیتابیس — همیشه
     اول، بدون این سند وارد مرحله بعد نشوید)
  2. db-architect (فقط اگر سند راه‌حل تغییر schema را لازم بداند)
  3. backend مطابق پشته: nodejs-developer (پشته Node.js/Next.js) یا
     dotnet-developer (پشته .NET)؛ برای فیچرهای یکپارچه‌سازی بین دو
     پشته، هر دو به ترتیب.
  4. frontend: nextjs-frontend-developer برای پشته Node.js/Next.js
     (بعد از این‌که backend داده لازم را آماده کرد)؛ در پشته .NET، خود
     dotnet-developer مسئول View است.
  5. qa-tester
  6. security-reviewer
  7. tech-lead (تایید نهایی فنی — آخرین مرحله)
- فیچر تا زمانی که tech-lead تایید نهایی ندهد «تمام» اعلام نمی‌شود.
- **حلقه‌ی بازخورد**: اگر qa-tester، security-reviewer، یا tech-lead
  مشکلی پیدا کرد، کار دقیقاً به agent مسئولِ همان بخش کد (و همان پشته)
  برمی‌گردد؛ بعد از اصلاح، فقط همان مرحله‌ی گزارش‌دهنده مجدداً اجرا
  می‌شود. حداکثر ۳ دور تکرار برای یک مشکل مجاز است.
- این قوانین علاوه‌بر سایر قوانین/کانونشن‌های ثبت‌شده در مستندات پروژه
  (CLAUDE.md یا معادل) اعمال می‌شوند، نه به‌جای آن‌ها.
